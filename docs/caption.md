# 画廊文案（给每一小时配一句话）

页面 https://zoe-wallpaper.lengjingxu.workers.dev 每张图下面显示的就是这段文案。
它只给看图的人读，不是工作记录。

## 怎么写

写一句到两句，**像人看着这张照片说的一句话**，不是总结这一小时干了什么。

- 长度：**18–45 个汉字**。超过 60 字在电视和手机上会被截断。
- 视角：从画面出发。她在做什么、屋里什么光、猫在哪、窗外是什么。可以带一点情绪或吐槽。
- 语气：平静、具体、有温度。像朋友在旁边轻声说的一句，不像旁白解说员。
- 允许留白：不必交代工作细节，看的人不需要知道你在改哪个 bug。

## 不要写

- 不要罗列工作事项（"排查了 A、修复了 B、部署了 C"）。那是 `topic` 字段的写法，不是文案。
- 不要日期时间开头 + 多段生活细节的日记体。
- 不要逐句描写画面里有什么（谁拿什么、桌上什么、窗外什么景）的报菜名式描写。
- 不要 AI 套话："总而言之""值得一提的是""不仅...更...""看似...实则...""不是...而是..."。
- 不要强行升华、灌鸡汤、正能量结尾。
- 不要出现具体项目名、公司名、客户名、人名、金额、内部代号。
- 不要 emoji。

## 例子

这一小时的内部记录（`topic`）是：

> 反复出现的未授权报错被追到工作台重构里，设备连接改回一小时窗口，最新改动确认已生效后执行，最后停在商户账单页问一个 id 是什么

合格文案：

> 追了一下午的报错，最后停在一个说不清的 id 上。窗外的云压得很低。

> 屋子暗下来的时候她还在屏幕前，猫已经睡在键盘边上了。

不合格（这些是工作记录，不是文案）：

> 排查未授权报错，重构工作台，回滚设备连接窗口，验证改动生效。

## 流程

每小时任务在写完整理之后，把这一小时的 `topic` 和画面要点交给「说人话大师」写这一句，
然后把返回的文案作为 `--caption` 传给 `zoe show`。**不要自己临时编**，也不要拿 `topic` 直接当文案。
